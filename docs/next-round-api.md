# 续局和换座接口

说书人页面在 `ENDED` 阶段的结束总结下显示 `src/storyteller/NextRound.tsx` 提供的“再来一局”。接口字段 `room.storyteller.canStartNextRound` 也仅在该阶段为 true。
点击只展开本地菜单，不立即发命令或清空总结：

- **保持原号码** → `keep`。
- **座位变动** → 再展开“说书人修改” `host` / “玩家重新扫码” `rescan`。

只有说书人能开启下一局。玩家页面展示结束总结和等待说书人开启的状态；不能发起续局。

## 选定方式后发送

```ts
{ type: "new_round", seatMode: "keep" } // 或 "host"、"rescan"
```

使用 `command` 信封，携带结束那一局的 `gameNo` 和本次唯一的 `commandId`。
同一请求重试复用 `commandId`；重复包不会多开一局或重复归档。
服务端将局号加一，返回 `SETUP`，保留当前配板作为下局起点，清空本局身份、聊天、行动、笔记及结果，归档上一局公开总结。
所有模式都先关闭入场；说书人核对配板后，通过已有 `open_registration` 确认开始/开放登记。

当前选择通过 `room.roundSetup` 返回：`mode` 和 `seatingConfirmed`。
明确选择续局方式会清除上一局尚未处理的换座申请，以本次选择为准；旧客户端不传 `seatMode` 时继续兼容旧的保留号码和审批申请流程。

| 方式     | 玩家设备和座位                                               | 发身份的时机                                                   |
| -------- | ------------------------------------------------------------ | -------------------------------------------------------------- |
| `keep`   | 原设备会话、座位 ID 和号码不变                               | 说书人确认配板并开放后，人数齐全且号码唯一就统一发放           |
| `host`   | 保留设备会话和座位 ID，号码由说书人统一修改                  | 先保存确认整张座位表，再由说书人开放                           |
| `rescan` | 清空本局登记，撤销所有旧玩家会话及恢复入口，保留说书人管理权 | 说书人开放后，所有人重新扫码登记；人数和号码校验通过后统一发放 |

## 说书人修改座位

在 `SETUP`、入场关闭、`roundSetup.mode === "host"` 时使用：

```ts
{
  type: "set_seating",
  expectedContextVersion: room.storyteller.contextVersion,
  seats: [
    { seatId: playerAId, number: 2 },
    { seatId: playerBId, number: 1 },
    // 必须包含当前全部登记玩家，每人一次。
  ]
}
```

一次提交整张表，支持两人交换或多人循环换座，不会因中间状态号码重复而失败。
服务端拒绝缺人、重复玩家、陌生座位 ID、重复号码、超出人数范围及过期版本；失败不会部分保存。
保存成功后 `seatingConfirmed` 为 true，原设备仍跟随对应玩家，刷新状态即可看到新号码，无需重新扫码。
在此模式下，玩家不能自行 `move_seat`，前端可依据 `self.canChangeNumber === false` 隐藏编辑入口。
移除登记会关闭入场并要求说书人重新确认表；仍可为剩余玩家确认后开放，让替补补齐空位。

## 玩家重新扫码

二维码指向原房间，并携带**新局号**，例如 `/join/ABCDEF?g=2`。`src/components/Invitation.tsx` 根据当前 `room.gameNo` 生成地址，扫码页读取 `g` 参数。

`GET /api/rooms/:code` 返回公开的 `gameNo`。扫码页核对二维码局号与当前局号一致后，提交：

```ts
// POST /api/rooms/ABCDEF/join
{ number: 8, gameNo: 2 }
```

重新扫码模式下必须带本局 `gameNo`。缺少或使用旧局号会被拒绝，避免上局页面或旧请求占入新座位；不要把过期二维码中的局号静默替换为当前值。
旧设备会收到既有 `session_revoked` 事件；前端清除该房间的旧玩家凭据并提示重新扫码，不要再用它自动重连。
同一房间的说书人会话继续有效。

重复号码仍可作为待确认登记显示，但不会发任何身份。所有人数齐全且号码互不相同后才统一发放；新登记者可用已有 `move_seat` 修正号码。
重新扫码生成新的座位身份，不会因为新玩家填了与旧玩家相同的号码，就把旧玩家的私人笔记归给他。旧私人笔记仍在存档，但新会话不继承其读取权限。

## 总结的保留

正常结束的本局总结仍读取 `room.recap`。进入下一局后，说书人通过 `storyteller.archiveGames` 选择局数，再请求 `GET /api/rooms/:code/history/:gameNo` 继续查看固定的上一局总结；其中的旧号码、身份和时间线不随新座位变化。
玩家只显示当前局信息；等待入座和新一局开局后均不返回旧笔记、旧公开记录或旧总结。上一局总结由说书人查看归档。
提前结束仍不自动公开身份复盘，沿用 [结束与复盘接口](endgame-api.md) 的规则。
