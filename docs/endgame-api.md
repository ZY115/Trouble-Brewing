# 结束判定与精简复盘接口

说书人界面通过 `src/storyteller/EndGame.tsx` 确认结束游戏，结束后展示结果和复盘。接口类型在 `shared/endgame.ts`，命令通过 Socket.IO `command` 信封发送，携带 `gameNo` 和 `commandId`。
兼容命令 `end` 只按“提前结束、未判胜负”处理，不自动公开身份。

## 一、系统建议与最终裁定分开

游戏进行中，说书人读取 `room.storyteller.endReview`：

| 字段                          | 含义                                                                         |
| ----------------------------- | ---------------------------------------------------------------------------- |
| `available`                   | 只在首夜、其他夜晚、白天为 true；可据此常驻显示结束按钮                      |
| `buttonLabel`                 | 未检测到已满足的条件：提前结束；有条件满足：结束游戏；已结束：已结束         |
| `suggestions`                 | 建议及依据；`met` 已检测到条件，`check` 仍需核对，`end_day` 等待确认当天结束 |
| `suggestedWinner`             | 唯一明确的建议胜方；缺少证据或建议冲突时不提供                               |
| `pendingActions / activeVote` | 结束确认框提示尚未完成的行动、投票；确认结束会取消这些操作                   |
| `key`                         | 本次确认内容的版本指纹；相关游戏状态或复盘改变后，旧确认会被拒绝             |

所有提示仅供说书人参考，**没有自动结束或自动决定胜方的逻辑**。关闭旧的规则提醒也不会消除结束判定依据。

目前处理暗流涌动的以下情况：

- 没有存活恶魔：先核对死亡快照中的猩红女郎继任/小恶魔自杀传位。仍有继任候选时只提示核对；无待处理候选时建议善良胜利。旧档缺少死亡快照则不猜测。
- 两人或更少存活且有存活恶魔：建议邪恶胜利。
- 圣徒因处决死亡：看处决当时的中毒/醉酒快照，不用当前状态倒推。已记录失能时不建议因圣徒获胜；缺少快照则交给说书人核对。撤销/更正处决会同步更新建议。
- 镇长：三人存活、镇长健康清醒、当天没有有效处决时，白天只显示 `end_day` 条件提示。确认结束当天，或正常进入下一夜时，才视为条件满足。即使“处决但没死”也属于发生过处决。
- 多项记录产生不同胜方的建议：不强行选边，要求说书人说明最终裁定。

镇长正常跨入夜晚时保存当天结束的快照，后续中毒不追溯改变它；若更正记录显示当天实际有处决，会撤回该建议。使用“更正阶段”会清除这项快照，避免误切阶段被当成有效日落。
这些判断仍依赖说书人录入的真实身份、状态和事件，不能发现未录入的线下特殊裁定。

角色规则核对来源：[猩红女郎](https://wiki.bloodontheclocktower.com/Scarlet_Woman)、[小恶魔](https://wiki.bloodontheclocktower.com/Imp)、[圣徒](https://wiki.bloodontheclocktower.com/Saint)、[镇长](https://wiki.bloodontheclocktower.com/Mayor)。

## 二、说书人确认结束

```ts
// key 必须来自用户打开确认框时看到的快照，不要在发送前悄悄换成最新值。
{
  type: "finish_game",
  mode: "normal",           // normal 正常结束；early 提前结束
  winner: "good",           // good 善良；evil 邪恶；none 未判胜负（仅 early）
  reason: "",               // 与建议不同、没有明确建议或有冲突时，正常结束必须填写
  endDay: false,             // 镇长当日无处决胜利，需明确确认时传 true
  confirmed: true,
  expectedReviewKey: review.key
}
```

- 说书人可以选择不同于系统建议的胜方，只需填写裁定说明；也可随时提前结束。
- `endDay: true` 仅限白天，且必须先完成或取消正在进行的投票。
- 正常结束必须选善良或邪恶胜利，同时公开身份复盘和最终生死；建议、最终胜方、裁定说明分别保存。
- 提前结束可选 `none`，不自动公开魔典或复盘。说书人仍可查看自己的复盘预览。
- 结束会取消未完成行动和投票、清除倒计时、关闭入场及邪恶频道；未送达的裁定草稿不会被算作已发生信息。
- 这不是阶段切换命令；未完成行动会列入核对，但不会阻挡说书人主动结束。
- 同一操作网络重试复用 `commandId`，独立操作生成新 ID；旧局命令会被拒绝。

结束后的 `room.result` 提供 `mode / winner / reason / endedAt / day / period`。
正常结束保存当时的系统建议，最终胜方始终以 `result.winner` 为准。
提前结束时，玩家端不接收含隐藏身份的系统建议。最终裁定说明是公开文本，不要把私人说明写入其中。

## 三、复盘汇总“发生了什么”

说书人始终可以读取 `room.storyteller.recapPreview`；玩家只有正常结束后才能读取 `room.recap`。
它们使用同一 `GameRecap` 类型：

| 字段                        | 内容                                                                             |
| --------------------------- | -------------------------------------------------------------------------------- |
| `gameNo / version / result` | 局号、复盘版本、最终裁定                                                         |
| `seats`                     | 按编号排序的开局真实/认知身份、最终真实/认知身份和生死；旧存档可能没有 `initial` |
| `redHerring`                | 最终登记的占卜误判目标座位 ID                                                    |
| `entries`                   | 按第几夜/天排序的关键事件，包含 `id / day / period / kind / text`                |
| `limitations`               | 数据范围、旧记录缺失提示                                                         |

时间线默认包括：下毒/保护/击杀的选择及确认效果、信息角色最终告知内容与真实答案、行动时失能情况、身份变化和恶魔继任、处决（含原因）以及必要的生死/状态调整。
每条都是玩家能直接读懂的一句话：

- “2 号投毒者毒了 8 号。”；只有玩家选择和“已收到”时写“想毒 8 号，没有生效。”，不推断下毒已生效。
- “1 号小恶魔袭击 10 号，10 号被保护，没有死亡。”
- “3 号共情者（中毒）得知「0」，真实应为「1」。”：`reference.truth` 保存健康时应得的答案，失能时也保留，仅用于复盘。
- “1 号酒鬼（以为自己是洗衣妇）得知「…」。”
- “2 号投毒者继任成为小恶魔。”、“7 号猎手被处决（提名了贞洁者）。”
- `set_alive` 可带 `reason`，写成“1 号死亡（10 号猎手开枪命中）。”；没有原因时为“（说书人登记）”。

手动勾选中毒只记录“N 号被说书人标记中毒”，不猜是谁下毒；说书人可补充线下原因。
信息角色使用送达时保存的参考和当时状态，后来的继任、毒状态改变不会改写此前事实；更正回复展示最终版并注明“（已更正）”。

不列出私聊、私人笔记、全量投票明细、未执行的待办和未送达草稿，也不把普通操作日志当成真实因果关系。
开局身份快照和结构化事件从此版本开始记录，不能凭旧存档中的最终状态编造缺失的历史。

## 四、补充和更正

```ts
{
  type: "edit_recap",
  entryId: "existing-id",    // 改写已有项；省略则新增线下说明
  expectedVersion: recap.version,
  day: 2,
  period: "NIGHT",
  text: "镇长将本夜击杀转移到 5 号（线下裁定）"
}
```

仅说书人可修改。自动生成条目的原始记录继续保留，手工说明覆盖展示文本；以后若更正相关事件，也应核对手工说明。
复盘的每一条玩家都能看到。游戏中这些改动不公开；正常结束后修改会立即更新玩家收到的复盘。
遇到版本冲突必须重新查看最新报告再保存，不静默覆盖。复盘文字编辑不会修改胜方或游戏事实。

新一局清空当前结果、复盘和记录；号码可保留、由说书人修改或让玩家重新扫码登记，详见[续局和换座接口](next-round-api.md)。上一局公开复盘保存为固定快照，由说书人通过 `storyteller.archiveGames` 选择局数，再请求 `GET /api/rooms/:code/history/:gameNo` 查看，不会被下一局身份或号码变化改写。
玩家只接收本局数据：本局结束时可查看本局复盘；续局后不再接收上一局复盘、笔记或公开记录。
